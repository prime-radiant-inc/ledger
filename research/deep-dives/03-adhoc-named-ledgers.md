## (b) Anatomy

**Scratchpad trio — append-only status tables with a fixed row grammar.** mcp-resilience header (created via `cat > ... <<EOF`): `# WS5 mcp-resilience run — base bd866b1ed` + `| Task | Status | SHA(s) | Notes |`. The parent's prompt dictated the grammar: append `| N | STARTED | - | <title> |` before dispatch, `| N | DONE | <sha(s)> | <one-line...> |` after review. working-state-metrics self-documents its own schema in the header: "Format: | task | STATUS | sha | notes |. STATUS one of: DONE, FAILED, BLOCKED, GATE (final gates), NOTE." Sidebar's header also carries a coordinator errata note ("plan's gate map cites the MAIN checkout path... that is a stale pre-worktree reference"). Notes cells grew huge — task C2-FIX's DONE note is a full paragraph of root-cause analysis.

**kata-fleet-ledger — sectioned situation board, not a log.** Headed by goal provenance ("Goal (Jesse, /goal)... Directive (Jesse, mid-flight): implementers run on opus/medium from now on"), then sections: `## Landed this phase`, `## Central gates` (incl. "Tree is FROZEN for commits until gates finish"), `## Agents running (worktree = ...)` with per-agent one-liners, `## Held, with reasons`, `## Merge discipline` ("Jesse's uncommitted App.tsx... every merge must be checked for those paths first; abort if touched"), `## Loose ends`. Later entries are explicit handoff notes: "a5a9 wedge-hunter agent KILLED at handoff... the PARTING LEAD — at GOMAXPROCS=1... emitted counter explodes to 1.4 BILLION."

**ask-user-impl-ledger — header block + task table.** Records worktree, branch, MERGE_BASE, plan/spec HEADs, baseline build status, model tiering, then `| Task | Status | Commit(s) | Gate/notes |`. Final row: `| JOB3 FINAL GATE | PASS (mod known-env) | HEAD 83d597526 | ... |`.

**rationale-ledger — keyed reference entries**, `## Subsystem` → `### SHA (date) — decision`, verbatim commit-body quotes, machine-readable cite comments (`<!-- cite: commit body of SHA fc4dcdc -->`).

## (c) What worked (cited)

- **Ledger as live IPC channel.** In both July 4 fleets the parent set up `Monitor: tail -F <ledger> | grep "DONE\|FAILED\|BLOCKED\|GATE"` — for ask-user *eleven seconds before spawning the child* (bc7448bd, 05:28:19), and with `2>/dev/null` before the file existed for mcp-resilience (59f97d2e, 17:52:46). The path+row-grammar was a pre-agreed contract; the parent also queried structured rows on demand (`grep "^| 8 " .../sidebar-rebuild-ledger.md`, 20:10:42).
- **Cross-coordinator resumability.** The ask-user endgame coordinator (agent-ae64c4b6, spawned 16:31 with "you inherit via external state, not context") was told "Maintain the ledger... append one row per job in the existing table format" and did, 5 edits to close-out (07-04).

## (d) Friction / failures (cited)

- **Repeated-edit wobble at birth:** mcp-resilience got two identical Edits 7s apart (17:53:29, 17:53:36) with a Read in between — the row-append via Edit-tool anchor matching is fragile for an append-only log (later state shows no duplicate, so one attempt failed or was corrected; a real append primitive wouldn't have this ambiguity). Coordinators mixed mechanisms: Bash heredoc create, Edit appends, `cat >>` appends.
- **Note-cell bloat / format drift:** the "one-line" notes rule drifted into multi-paragraph essays inside table cells (C2-FIX row; Task 21 row), degrading the grep-ability the parent's Monitor depended on.
- **Write-only ledger:** rationale-ledger.md was never read by any archived session — a deliverable produced, never consumed (within the archive).
- **tmp-scoping did not directly bite, but only because of belt-and-suspenders:** no session ever attempted to read the 59f97d2e scratchpad ledgers after 07-05; the parent had duplicated in-flight state into durable memory (`~/.claude/projects/.../memory/project_serf_ux_diagnostic.md`, "⚡ IN-FLIGHT RUNTIME STATE (written 2026-07-04 pre-compaction — read this FIRST on resume)"). The ledgers' contents (commits) lived on in git. The insurance work was itself a cost.
- **The neighboring skill-mandated ledger family failed exactly where these ad-hoc ones invested:** memory file `sdd-ledger-staleness.md` (07-06, superpowers-workspace) documents Jesse-reported failures of SDD's fixed-path `progress.md`: "No plan identity... A fresh session on a follow-up plan in the same worktree reads the old plan's ledger as its own"; follow-up controllers invented `progress-p2.md`/`progress-p3.md` "to dodge collisions"; briefs overwritten; artifacts leaked into git 3+ times. The ad-hoc ledgers here avoided this precisely by unique naming (feature-scoped filenames) and headers binding ledger→plan/base-SHA.

## (e) Implications for a generalized ledger tool

1. **Append needs to be a primitive, not an Edit.** Every agent reinvented append (heredoc, `cat >>`, anchor-Edit) and the Edit path glitched. A `ledger append` op with keyed rows would remove the wobble and keep the grammar machine-stable.
2. **The ledger is a channel as much as a file.** The strongest observed pattern is parent-tails-child via pre-agreed path + row grammar (`DONE|FAILED|BLOCKED|GATE`). A tool should make "watch for status transitions" first-class instead of tail+grep contortions.
3. **Identity binding beats path convention.** The failures next door (sdd-ledger-staleness) came from a fixed path with no plan identity; the successes here all carried headers binding ledger→plan, base SHA, worktree, format spec. A ledger tool should stamp scope/plan/base-ref metadata and refuse cross-plan resume.
4. **Separate the two record types.** Two distinct shapes recurred: append-only event rows (task status) and a mutable situation board (kata-fleet's sections: running/held/frozen/loose-ends). Cramming analysis prose into log-row cells was the main drift; a tool should give a keyed notes area alongside the log.
5. **Lifecycle: promote or expire, explicitly.** Ledgers earned durability by graduation (kata-fleet committed to git with a session-link trailer) or died safely because state was manually double-written into project memory. Session-scoped tmp placement is fine for IPC-style ledgers, but a tool should offer an explicit end-of-run "promote to durable / summarize into memory / discard" step so agents stop paying the insurance tax by hand.
